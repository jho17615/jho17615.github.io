QR 스캔부터 주문 접수·매출 통계까지 이어지는 테이블 주문 시스템. Spring 없이 MVC 라우팅 구조를 직접 설계하고 팀 공통 아키텍처를 잡는 것이 핵심 과제였음.

담당 영역

공통 MVC 프레임워크 설계, 관리자 기능(매장·메뉴·QR·매출), DB 스키마

주요 기능
  • QR 스캔으로 테이블·매장 자동 식별 및 비접촉 주문 처리
  • 관리자 매장·메뉴·QR 코드 생성·수정·삭제 및 매출 통계 조회
  • Admin·Owner·Customer 3계층 역할 기반 접근 제어
  • 매출 다중 시간 단위(일·주·월·시간) 집계 및 메뉴 Top3 랭킹
기술적 도전 & 해결
  • 경량 MVC 직접 구현 → HandlerMappingListener가 actionMapping.properties를 읽어 Controller 등록, DispatcherServlet이 Method.invoke로 URL 기반 동적 디스패치
  • GET 파라미터·JSON Body 이중 처리 → BufferedReader로 raw body 읽기 → Gson 파싱 → request.setAttribute 전달
  • 3계층 역할 분리 → Owner 로그인 시 세션에 user+store 객체 함께 저장, 이후 모든 요청에서 매장 컨텍스트 자동 바인딩
  • 데이터 무결성 가드 → 매장·메뉴 삭제 시 countPendingOrders/isMenuInActiveOrders 선행 검사 후 IllegalStateException 차단
  • SQL을 dbQuery.properties로 외부화 → 재컴파일 없이 쿼리 수정 가능한 구조 확보
결과/의의
  • Spring이 추상화하는 Reflection 기반 MVC 디스패치와 HandlerMapping을 직접 구현하며 프레임워크 내부 동작을 코드 수준으로 이해
  • QR→테이블→매장 계층 구조로 매장별 독립 QR 운영, ON DUPLICATE KEY UPDATE로 재생성 시 기존 QR 원자적 교체
  • SQL 외부화·관심사 분리를 MyBatis 없이 직접 설계

담당 영역

SSE 기반 실시간 처리 파이프라인, HWP 바이너리 파서, 프론트엔드 인증·대시보드 전반 (FastAPI + React/TypeScript + SQLite)

주요 기능
  • SSE 5단계 진행률 스트리밍 → 파일 수신(10%) → 텍스트 추출(50%) → AI 분류(65%) → 요약(90%) → DB 저장(100%) 실시간 이벤트 전송
  • 이중 취소 구조 → uuid task_id를 응답 헤더로 전달, AbortController(SSE 끊기) + cancel_flags(백엔드 루프 탈출) 동시 실행
  • HWP 파서 → OLE 컨테이너 오픈·zlib deflate 압축 해제·32bit 레코드 헤더 비트필드 파싱, OCR 전처리(LANCZOS 2배 업스케일·Contrast×1.8·Sharpness×2.0), CJK 가비지 필터로 인코딩 오염 해결
  • 카테고리 분류 2단계 전략 → 1단계: 파일명 키워드 힌트 매칭으로 LLM 호출 없이 즉시 분류, 판단 불가 시에만 2단계 LLM 사용
  • Map-Reduce 요약 + LLM 파라미터 튜닝 → ThreadPoolExecutor(3) 병렬 청크 요약(temp=0.05) → 카테고리별 포맷 가이드 7종 최종 요약(temp=0.1), 정규식 후처리로 출력 품질 안정화
  • 프론트엔드 → 쿠키 자동 로그인, fetch() + getReader() + TextDecoder SSE 수동 수신, 드래그&드롭·300ms 디바운싱·스마트 ellipsis 페이지네이션
기술적 도전 & 해결
  • HWP 지원 라이브러리 부재 → HWP 포맷 스펙 직접 분석해 OLE·zlib·비트필드 구현, OCR 전처리(업스케일·대비)와 CJK 필터로 저화질·인코딩 오염까지 대응
  • 로컬 LLM 수십 초 추론 중 취소 불가 → SSE 헤더에 task_id 삽입, AbortController + cancel_flags 두 경로 동시 실행해 진행 단계 어디서든 즉시 종료
  • EventSource POST·쿠키 인증 미지원 → fetch() + response.body.getReader() + TextDecoder로 SSE 수동 파싱, 기존 쿠키 인증 흐름과 완전 호환
  • LLM 호출 비용·지연 최소화 → 파일명 키워드 힌트 1차 판단으로 분류 가능한 경우 LLM 아예 미호출, 분류 단계 지연 제거
결과/의의
  • 공개 라이브러리가 없는 HWP 포맷을 바이너리 스펙 분석으로 직접 지원해 PDF·DOCX와 동등한 추출 품질 달성
  • AI 처리의 긴 대기를 SSE 단계별 피드백 + 이중 즉시 취소 구조로 UX 저하 없이 해소
  • 2단계 분류 전략 + LLM 파라미터 튜닝 + 출력 후처리로 로컬 소형 모델(qwen2.5:3b) 환경에서도 카테고리별 구조화된 요약 안정화

MediaPipe 손가락 숫자 인식

MediaPipe 손 관절 추적 + Random Forest 기반 0~9 제스처 실시간 인식 ML 파이프라인

YEAR2024
ROLE개인 프로젝트
STACKPython · MediaPipe · OpenCV · scikit-learn · Random Forest
GitHub ↗
자세히 보기 ▾
배경

터치스크린은 촉각적 구분이 없어 시각장애인의 정보 접근성을 심각하게 제한함. 음성 안내는 보안 노출 위험이 있어, 카메라와 컴퓨터 비전 기술을 활용한 대안적 인터페이스를 고안함. 화면을 보지 않고도 손가락 제스처만으로 0~9를 정확히 입력할 수 있는 비접촉 인식 시스템을 단독 설계·구현함.

주요 기능
  • MediaPipe Hands로 손 랜드마크 21개(x·y·z)를 실시간 추출, 양손 126차원 특징 벡터 생성
  • 0–5는 한 손, 6–9는 두 손을 요구하는 제스처 규칙 적용 및 자동 판별
  • 제스처별 1,000샘플 웹캠 직접 수집, 총 10,000샘플 구축 + JSON 파일 퍼시스턴스 (main.py)
  • 실시간 좌우 반전(Mirror Flip)으로 사용자가 거울처럼 직관적으로 손 위치 확인 가능
  • Random Forest(100 트리) 학습 시 재현 가능한 80/20 분리(random_state=42) 및 트리 수별 학습/검증 정확도 그래프 생성 (STU.py)
  • 클래스(0–9)별 Precision·Recall·F1-score를 classification_report로 출력해 숫자별 오인식 패턴 분석
  • 학습된 모델을 실시간 로드하여 제스처 클래스와 신뢰도(Confidence)를 화면에 오버레이 (exe.py)
기술적 도전 & 해결
  • 한 손/두 손 혼재 시 특징 벡터 길이 불일치 → 두 번째 손이 없을 때 63차원(21×3)을 0으로 패딩하여 항상 126차원 고정
  • 6–9 제스처에서 한 손만 잡힐 때 오인식 → 수집 단계에서 두 손 랜드마크가 모두 감지된 프레임만 저장하도록 조건 분기
  • 트리 수 증가에 따른 과적합 추이 확인 → 1→100 트리를 반복 학습하며 단계별 train/test 정확도를 기록하고 그래프로 시각화
  • 모델 파일 구조 버전 호환 → joblib.load 결과가 dict인지 단순 모델인지 분기 처리로 하위 호환 유지
결과/의의
  • MediaPipe → 특징 추출 → Random Forest → 실시간 추론의 전체 ML 파이프라인을 단독 구현
  • 클래스별 정밀 평가(Precision·Recall·F1)로 단순 정확도를 넘어 숫자별 오인식 취약 구간까지 정량 분석
  • 데이터 수집(main.py) · 모델 학습(STU.py) · 실시간 인식(exe.py)의 역할 분리로 각 단계 독립 실행 가능
  • 향후 웹 대시보드 연동 시 exe.py를 현장 측 인식 엔드포인트로 활용 가능한 확장 구조
